Better Data Modeling: An Introduction to Agile Data Engineering Using Data Vault 2.0

Kent Graziano · 2015 · data vault

Highlights (AI · MDDE/SBM lens)

AI-distilled highlights, not personal reading highlights — the ideas in this book that connect to Jaco's MDDE / Structure-Beats-Magic work, selected and paraphrased through that lens. Paraphrased (never verbatim); verbatim quotes await the book text.

  • Data Vault as the agile answer to warehouse rigidity — Graziano's framing is that hub/link/satellite modeling absorbs change by addition instead of restructuring; new sources and attributes bolt on without breaking what exists, which is what makes iterative delivery honest rather than aspirational.
  • Business keys anchor everything — start from the identifiers the business actually uses, not the surrogate keys of source systems; the hub is a bet that business identity is the most stable thing in the enterprise.
  • Separating identity, relationship, and context is the whole trick — three table shapes, each isolating one rate of change; a small vocabulary of patterns repeated everywhere is precisely the pattern density that later made vault generation (VaultSpeed and kin) possible.
  • Standards make modeling teachable — Graziano writes as the great explainer of the Linstedt school: because DV is rule-bound, an introduction this thin can genuinely transfer the method — you cannot write the 100-page primer for an ad-hoc approach.
  • Model changes should be cheap by design — the agility argument is structural, not procedural: sprints do not make a brittle model agile, the model shape does; process borrows its agility from architecture.
  • Auditability comes free when you never update — insert-only loading with recorded lineage means the warehouse can always answer where a number came from; compliance as a property of the pattern rather than an afterthought.

Structure beats magic.
