Data Model Patterns: A Metadata Map

David C. Hay · 2006 · data modeling

★★★★☆

Why this is in my collection

Highlights (AI · MDDE/SBM lens)

AI-distilled highlights, not personal reading highlights — the ideas in this book that connect to Jaco's MDDE / Structure-Beats-Magic work, selected and paraphrased through that lens. Paraphrased (never verbatim); verbatim quotes await the book text.

  • A data model of the IT industry itself — Hay turns the modeling lens back on its own discipline and builds an enterprise model of information technology's artifacts: entities, attributes, programs, databases, requirements; the boldest possible demonstration that everything, including modeling, can be modeled.
  • Metadata is just data whose subject is data — the book dissolves the mystique around metadata repositories by modeling them with ordinary entity/relationship discipline; the conceptual foundation under every model repository MDDE tooling (CrossModel included) instantiates.
  • A repository model is the precondition for generation — once models, mappings, and rules are themselves stored as structured data, transformations over them (validation, comparison, code generation) become queries and programs; this book maps the data structures a data engine runs on.
  • The Zachman framework given a backbone — Hay organizes the map along the framework's perspectives, showing how business-view concepts trace down to implementation-view artifacts; the traceability spine that lets a change in the conceptual model propagate to generated code.
  • Row-two/row-three discipline: business model vs system design — keeping the business's view and the designer's view as distinct, mapped layers is exactly the logical/physical separation that makes solutions regenerable across platforms.
  • Even meta-models obey the same patterns — party, document, activity structures reappear one level up, in the model of models; pattern density goes all the way down, which is why a generic modeling metamodel is feasible at all.
  • Written before its market existed — in 2006 few needed a rigorous metadata map; in the age of catalogs, lineage tools, and model-driven generation, this is the reference model the industry keeps reinventing pieces of.
