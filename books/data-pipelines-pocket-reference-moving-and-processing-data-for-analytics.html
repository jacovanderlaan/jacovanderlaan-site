Data Pipelines Pocket Reference: Moving and Processing Data for Analytics

James Densmore · 2021 · data engineering

Why this is in my collection

From the publisher:

Data pipelines are the foundation for success in data analytics. Moving data from numerous diverse sources and transforming it to provide context is the difference between having data and actually gaining value from it. This pocket reference defines data pipelines and explains how they work in today's modern data stack. You'll learn common considerations and key decision points when implementing pipelines, such as batch versus streaming data ingestion and build versus buy. Highlights

  • Every pipeline is the same pipeline — Densmore's extract-load-transform anatomy repeats across all his examples with only source and target swapped; that sameness is the strongest field evidence that pipelines are pattern-dense enough to be generated from a model instead of hand-coded.
  • ELT wins because transformation belongs where the model lives — pushing transformation into the warehouse puts the logic next to the modeled data; from an MDDE angle this is the precondition for deriving that logic from the model itself.
  • Validation belongs inside the pipeline, not after it — his data-validation tests (row counts, duplicates, referential checks) are rules embedded in the flow; a pocket-sized version of rules-as-the-third-pillar alongside data and (now) AI.
  • Build vs buy is really pattern vs exception — the buy decision works where the ingestion pattern is commodity and breaks where organization-specific logic hides; the same boundary MDDE draws between generatable structure and hand-written exceptions.
  • Incremental loads are a contract, not a trick — reliable incremental ingestion depends on agreed keys and change-detection semantics, i.e. on the model; get the metadata wrong and no orchestrator saves you.
  • Orchestration is plumbing, patterns are the asset — Airflow and its rivals churn like all platforms; the dependency graph they execute is derivable from the model, which is where the durable value sits.
